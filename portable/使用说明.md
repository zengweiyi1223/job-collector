# JDIA 岗位收集 · Windows 候选包

这是待验收的免安装候选包。适用已安装 Google Chrome 的 Windows x64 电脑。无需安装 Python、Node 或 BossHunter；不支持手机、Mac、Windows ARM。尚未公开发布或完成第二使用者验收。

1. 将整个 ZIP 解压到有写入权限的独立文件夹，不要直接在压缩包中运行。
2. 双击 `Start-Collector.cmd`。程序启动本机服务，打开专用 Chrome、BOSS 页面、本机配对页和查询页；启动不会采集。
3. 首次由本人在专用 Chrome 正常登录 BOSS。将本机配对页的码复制到查询页，点击连接。
4. 需要采集时才点击开始。默认广州、全职，自选关键词；最多20次新详情/3批，已存岗位跳过且不更新。遇验证提示暂停，由本人检查任务页后明确继续；其他访问限制停止。
5. 在查询页搜索、筛选、展开JD、查看原链接或修改关注。不关注仍保留。区域/薪资/规模筛选仅作用于本地数据，未知字段不匹配。
6. 结束使用双击 `Stop-Collector.cmd`。会先请求活动采集停止，再关闭归属确认的本机服务；浏览器和数据保留。程序重启后配对码变化，需重新连接。

## 数据、升级与恢复

`user-data/jobs.db` 是你的 SQLite 数据，`user-data/chrome/` 是专用浏览器配置，`user-data/logs/` 是本机诊断日志。均只保存在自己的电脑，禁止放入公开代码仓库或发给他人。各人解压自己的包，有自己的数据库和浏览器配置。程序不会读取普通 Chrome 的账号配置。

备份：正常停止程序后，单独复制 `user-data/jobs.db` 到自己选择的安全位置；浏览器保持时不要复制其配置。恢复：停止程序，保留当前数据库作为另一份备份后，再由本人用已知良好的备份替换数据库，启动并查询核对。此包无自动迁移或自动覆盖主库功能。

升级：解压新版到新文件夹；停止旧服务后再迁移数据库。保留旧包与原数据，确认新版本后再清理。不要把新 ZIP 覆盖解压到正在使用的数据目录，不要同时启动多个使用相同端口的版本。

## 连接与故障

默认端口为Web8688/内部桥接3458/专用Chrome9422，均仅本机监听。端口被其他应用或开发版占用时会拒绝启动，不终止未知进程；请先正常结束另一版本。网页查询不依赖BOSS在线，采集仍需专用浏览器及有效登录。

若需访问将来的公开网页，按项目提供的准确HTTPS来源创建 `settings.json`，仅设置 `public_origin`，例如 `{"public_origin":"https://你的账号.github.io"}`；程序重启后生效，错误来源会被拒绝。尚未配置/发布真实公网目标，本地通过不代表公网可用。不要放宽到任意来源，配对码只从本机页取得，浏览器本地网络授权由本人正常操作。

启动失败时查看 `user-data/logs/`，先确认Chrome、端口及解压路径；不要反复采集或更改日常浏览器配置。开发验证可用 `Start-Collector.ps1 -NoOpen -NoBrowser -Port 8690 -BridgePort 3460 -ChromePort 9430`，这是无源站检查入口，不是日常必需步骤。
